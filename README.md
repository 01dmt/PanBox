# 影库

本地优先的 115 / ED2K 影视资料库。SQLite 保存原始来源、解析元数据和 TMDB 关联；React 界面用于检索、筛选、审核候选、管理导入，并向其他项目提供资源查询 API。

## 已实现

- 导入 `115.com`、`115cdn.com` 分享记录，完整保留原始标题和链接。
- 从一行中的多个 ED2K 链接提取文件名、大小、哈希、季集、分辨率、编码、HDR、音轨和发布组。
- 按作品聚合多条来源，ED2K 使用哈希幂等去重。
- TMDB 分层搜索电影、剧集和多类型结果；支持发布文件名别名、显式 TMDB ID、年份回退和跨类型纠错。
- 匹配前按需读取可公开访问的 115 分享目录，将文件夹名和发布文件名缓存为搜索别名，并用季集标记辅助判断剧集类型。
- 目录扫描记录真实文件、完整性和扫描边界。完整目录中的季集文件可排除电影候选；单个视频只提供名称证据，不直接认定为电影。同名歧义时进一步核验 TMDB 英文原名和别名，分享名与实际文件冲突则保留审核。
- 高置信度批量自动关联，低置信度进入人工审核。
- 仅当 TMDB 正常搜索及规则过滤后没有候选时，使用 IMDb 精确片名和年份定位，再通过 IMDb ID 反查并回核 TMDB；详情页保留核验结果。
- TMDB 关联后，自动合并中英文标题形成的重复作品记录。
- 桌面三栏管理界面和移动端列表/底部详情抽屉。
- 顶部放大镜按钮或回车可搜索本地缓存资源，支持片名、年份、TMDB ID、ED2K 文件名、115 缓存文件名/路径/分享标题；保留输入即筛选，清空按钮恢复当前视图。搜索不访问 115 或 TMDB。

## 数据模型

- `media_items`：作品级记录与 TMDB 元数据。
- `source_records`：115 分享或具体 ED2K 文件，可多对一关联作品。
- `tmdb_candidates`：待审核的候选结果与置信度。
- `imports`：每次导入的文件摘要和新增/重复/错误统计。
- `imdb_lookups`：每部作品最近一次 IMDb 辅助定位证据与未采用原因。

数据库默认位置：`data/media.db`。

115 目录快照存于 `source_records.metadata_json.share_snapshot`。新版快照包含 `version`、`complete`、`incomplete_reasons` 和 `files`；旧版成功快照下次匹配时自动刷新。默认最多扫描 3 层子目录、240 条目录项、12 次分页请求。字幕、预告和花絮不作为正片计数；压缩包和 ISO 不视为单个视频。网络读取在 SQLite 写事务之外执行。

115 明确返回 `4100010`（分享已取消）或 `4100009`（链接已失效）时直接删除该来源及快照，不再缓存失效状态。启动时也清理旧缓存中的已取消或失效分享。失去全部来源的未确认作品一并删除；其他 115/ED2K 来源以及已确认的 TMDB 元数据保留。待处理作品移除来源后会清除旧候选，避免继续使用已删来源的证据。访问码错误、缺少访问码和网络故障不作为失效处理，不据此删除链接。原始导入文本与历史备份不会修改；重新导入旧文本后，重新检测到失效的链接仍会被清理。

## 全量分享检查

`python3 app.py check-shares` 对全部 115 来源（已匹配与待处理）执行一次检查，开始前自动创建 SQLite 一致性备份。相同分享码和访问码只检查一次；每个分享只请求根目录 1 条记录，不递归扫描、不下载、不转存、不发送登录 Cookie。删除条件仅为明确的 `4100010` 或 `4100009`，其他异常保留来源，确认过的 TMDB 关联不解除。ED2K 不属于 115 分享检查范围。

- Web 刮削与检查进程共用 `data/share115-request-gate.json` 文件锁，全局串行，每次请求结束后至少等待 5 秒；检查每 100 个分享休息 120 秒。这是本程序的保守设置，不是 115 官方公布的安全配额。
- HTTP 401/403/405/429、验证码/访问限制、非 JSON 返回及未识别的业务错误触发持久停止；重启服务不会解除，不能靠连续重试、更换账号/域名/IP来恢复。普通网络错误也立即暂停此次全量检查，不误删、不自动重试。
- 页面显示检查进度和暂停按钮；`GET /api/share-audit` 查询只读摘要，`POST /api/share-audit/pause` 请求暂停。暂停最迟在当前分享检查（含限速等待）结束后生效。
- 队列进度保存在数据库同目录的 `<数据库名>-share-audit.json`，仅保存未完成的来源 ID 和汇总计数，不保留已取消 URL 或目录快照。`python3 app.py check-shares --resume` 继续未处理部分；访问保护触发后须先人工确认恢复，不能仅靠 `--resume` 绕过保护。
- 检查不重新缓存成功目录，保留现有文件名缓存；完整目录更新仍由用户发起刮削。电脑休眠或进程被终止会中断检查，可从断点继续。

## TMDB

复制环境变量模板：

```bash
cp .env.example .env
```

优先填写 TMDB v4 Read Access Token：

```dotenv
TMDB_API_TOKEN=your_v4_read_access_token
```

也支持 v3 API Key：

```dotenv
TMDB_API_KEY=your_v3_api_key
```

批量匹配：

```bash
python3 app.py match --limit 100
```

自动关联阈值为 `0.90`，且第一候选需要至少领先第二候选 `0.08`；本地无年份时保留原有的“主标题精确且领先至少 `0.12`”例外（最低 `0.88`）。同名电影/剧集、版本歧义、合集、中英文片名矛盾及季集文件与电影类型冲突均进入“待确认”，不因搜索排名靠前而提高置信度。

未关联作品的“TMDB 匹配候选”标题旁提供独立放大镜入口，可自行输入片名、选择电影/剧集、包含成人内容及翻页。`GET /api/tmdb/search` 仅执行一次指定页的 TMDB 搜索，保持返回顺序，不套用本地年份、语言优先或自动关联度筛选；仍排除人物及缺少年份的条目。本页排除数单独展示，页码沿用 TMDB 原始分页（最多 500 页），不把过滤后本页数量当作全局总数。搜索结果不写入数据库、不覆盖已存候选、不触发 115/IMDb；只有用户点“关联”才通过既有人工关联流程写入。结果提供原名、年份、类型、ID、简介与官网链接；切换作品或修改搜索条件会取消旧请求，避免旧结果串到新作品。

TMDB 条目必须提供发行年份（电影）或首播年份（剧集）。缺少年份的条目直接从候选中排除，不展示、不参与分差计算，也不能通过手动输入 ID 关联；这不限制本地文件名缺少年份但 TMDB 年份完整的作品。此规则不解除已经确认的关联。

本地作品已有年份时，普通 TMDB 搜索将该年份作为硬条件：其他年份即使同名也排除，不参与候选排序或分差计算，单独评分为零。作品年份优先于来源中的其他年份；本地和来源均无年份时不施加年份限制，继续通过名称、类型和候选差距判断。唯一例外是下述经 IMDb 精确匹配且双向 ID 核验通过的后备定位，不适用于普通同名候选。

按资料库偏好，同一年、同一媒体类型内，存在名称精确匹配且通过校验的高分中文候选时，排除同样名称匹配的纯英文标题候选。没有符合条件的中文候选时保留英文结果；不同年份、电影与剧集不跨组排除，多个中文候选仍需消歧，显式指定的 TMDB ID 不因语言偏好被移除。该规则是候选选择偏好，并不表示纯英文条目本身有误。

同名同年的多个高分剧集候选仍有歧义时，按需查询 TMDB 分季集数。支持实际视频文件中的 `S01E01-E79`、`S01E01-S01E79`、`S01E01-79` 及逐集文件；字幕、预告、重复清晰度不增加集数，分享标题和目录名不能代替实际文件。只有资源从第 1 集连续覆盖、唯一候选的对应季集数精确一致且 TMDB 总集数自洽、其他同组候选的对应季确实容纳不了资源集号时，才将冲突候选降至最高 79% 并允许原有阈值规则自动关联。不能把仅下载了部分剧集当作全季，也不按资源文件数量或 TMDB 季数多少直接选择。缺集、跨季范围、目录未扫描完整、剧集仍在更新、TMDB 缺项或查询失败、多个候选都能容纳资源时继续审核；显式 TMDB ID 不被该规则覆盖。比较依据保存在候选的 `payload_json._match_evidence.season_episode_comparison`，已确认关联不自动改动。

## IMDb 辅助定位

- 仅 `search_media` 的正常 TMDB 搜索没有可用候选时触发；有候选（包括低分、待确认）、已关联或 TMDB 请求失败时不触发。
- 本地或资源文件必须提供唯一可核对的年份。IMDb 的片名与已有标题/发布名别名经大小写、全半角和空格归一化后必须完全一致，年份必须相同；不删标点、副标题或续集标记，不使用模糊相似度，也不把“中文查询返回某个英文结果”当作名称一致。
- 使用 IMDb 公开结构化检索，不需要额外 API Key；最多查询 4 个已有名称，排除人物、单集和游戏。多个同名同年的 IMDb 条目不自动选择。
- 唯一 IMDb ID 通过 TMDB `/find/{imdb_id}` 反查，必须得到唯一作品，详情中的 IMDb ID 和媒体类型必须一致，且 TMDB 本身须有年份。
- 经用户授权，若 IMDb 片名和年份与本地精确吻合，且上述双向 ID 核验通过，允许以 IMDb 年份为本地作品年份关联到 TMDB，即使 TMDB 标注年份不同。两边的年份、ID 和例外依据均保留在核验记录中；作品合并时也保留 IMDb 核验年份，TMDB 原始 `release_date` 不改写。
- 此例外不修改 TMDB 官网、原始文件名或链接，也不绕过类型、资源冲突和歧义检查。缺少 TMDB 年份、IMDb 匹配不唯一、ID 回核失败、名称或本地年份不一致时仍不能采用。
- IMDb 公共接口不可用时记录失败原因，正常 TMDB 流程不受影响。修改本地标题、年份或类型后会清除旧核验记录；已确认关联不会被自动重新刮削覆盖。

片名识别保留原始标签和链接，分别提取方括号、`中文名 (年份) - 英文发布名` 以及 `BDRip` 后的有效别名，过滤 `1080p`、`REMUX` 等技术信息。规范的资料库标题不会再次按文件名截断，避免把片名里的数字误当发行年份。

普通搜索无法可靠匹配时，使用 WordNinja 为纯英文字母连写生成空格变体，例如 `Blackswan` → `Black swan`；不推测 `EVA30111` 这样的版本简称。分词只改变搜索词，不降低匹配标准。待确认候选按需补查 TMDB 英文名称、官方别名和多语言译名后重新评分；补查失败保留审核。匹配证据保存于候选的 `payload_json._match_evidence`。

## 公共资源查询 API

通过 TMDB ID 查询本地已关联作品及其全部资源。接口会返回 115 分享链接/访问码和 ED2K 链接，必须配置 API Key，并建议只通过 HTTPS 反向代理公开。

```dotenv
MEDIA_API_KEY=change-this-to-a-long-random-key
```

请求：

```http
GET /api/media/tmdb/{tmdb_id}/resources
X-API-Key: your-api-key
```

例如：

```sh
curl -H 'X-API-Key: your-api-key' \
  http://127.0.0.1:8088/api/media/tmdb/123/resources
```

成功响应包含 `media`（作品及 TMDB 元数据）和 `resources`（全部来源记录）。TMDB ID 不存在或本地没有对应作品时返回 `404`；未配置 Key 返回 `503`，Key 错误返回 `401`。当前接口为只读，不访问 TMDB 或 115，不检查分享实时有效性。

## 资料库筛选

首页默认显示「有资源」作品，即本地至少保留一条 115 或 ED2K 来源的作品。
切换「全部作品」或「无资源」仍能查阅保留的 TMDB 元数据，不删除任何作品或来源。
「有资源」只表示本地缓存中存在来源记录，不代表链接实时可访问；筛选只查询本地数据库，不请求 115、TMDB 或 IMDb。

- 常用筛选：资源有无、电影/剧集、115/ED2K、匹配状态。
- 「更多筛选」：年份或年代、题材、国家/地区、清晰度、视频编码、动态范围。年份优先使用本地年份，缺失时采用 TMDB 发行年份；题材、地区来自已缓存的 TMDB 数据。
- H.265、H265、X265、HEVC 归为同一编码组；H.264、H264、X264、AVC 同理。HDR 包含 HDR10/HDR10+，杜比视界可与 HDR 同时存在。未识别技术信息不会被推断成 SDR。
- 来源类型、清晰度、编码、动态范围必须同时满足于同一条来源；不会把一部作品的 115/1080P 和 ED2K/4K 合并视为存在 115/4K。
- 列表显示符合条件的来源数量与清晰度，详情栏只展示这些来源。原始来源总数仍保留，未符合筛选的资源并未删除。
- 已选条件可单独移除，「清除全部筛选」同时清除搜索词并显示全部作品；筛选变化回到第一页。快速切换会取消旧请求，避免过期结果覆盖当前结果。
- 进入不同数据视图（资料库、待匹配、多来源）会重置筛选，避免其他视图的条件隐藏待处理项；进入设置/导入后回到原数据视图则保留条件。
- 手机端筛选换行展示，无需横向滑动；高级条件可收起，结果数量和已选条件仍可见。

`GET /api/media/filters` 返回全库缓存中的年份、题材和地区选项（不是当前筛选结果的动态统计）。
`GET /api/media` 新增 `availability=all|available|missing`、`year=2024|2020s|unknown|all`、
`genre=<TMDB genre ID>|all`、`country=<ISO country code>|all`、`quality=2160P|1080P|1080I|720P|480P|unknown|all`、
`codec=h265|h264|av1|unknown|all`、`hdr=dv|hdr|sdr|unknown|all`；API 默认仍为全部作品以兼容原调用。
响应新增 `media_year`、`matched_source_count`、`matched_source_ids` 和 `matched_qualities`。
`status=pending` 保持「所有未匹配」语义，新增 `status=unsearched` 仅选择尚未搜索的作品。
